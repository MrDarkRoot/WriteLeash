The [native README](../../../experiments/native_tx_state/README.md) links preserved evidence, including [integrated audit](../../../experiments/native_tx_state/evidence/2026-09-23-integrated-audit-e97f19b.txt), [transition](../../../experiments/native_tx_state/evidence/2026-09-23-cc020-cc022-a996eed.txt), [numeric](../../../experiments/native_tx_state/evidence/2026-09-23-cc030-cc033-7c1eb35.txt) and [numeric contention](../../../experiments/native_tx_state/evidence/2026-09-23-cc036-numeric-contention-62c7f90.txt). **REPORTED:** The strongest established property is top-level transaction denial after a supported UPDATE authority violation, including caught errors/savepoint recovery, within the fixture's restricted-writer boundary. The complete denied transaction's transactional effects are checked after termination. This is stronger than merely rejecting one statement.

**NOT VERIFIED:** task-wide authority; identity that cannot be self-renewed; durable consumption across transactions; shared allowance across workers; atomic operation deduplication; expiration/revocation; arbitrary indirect writes; economic truth; managed deployment; production readiness; stable overhead. Canonical task-wide tests remain requirements, not passing evidence.

## Architecture and deployment gaps

1. **Durable authority has a different lifetime.** Backend memory intentionally resets at top-level transaction end. A shared task allowance needs a trusted durable object and atomic consumption with affected rows. A transactional SQL ledger may be enough for *committed-effect ceilings*. It does not automatically implement the native fixture's stronger sticky-denial semantics after caught subtransaction errors. Compare both contracts explicitly.
2. **Identity is part of enforcement.** An agent-selected task string or session header permits allowance renewal. An issuer must bind task, writer, policy, expiry and lineage, and prevent the writer from creating/replenishing grants. An opaque ID alone is not authorization.
3. **Concurrency needs a shared serialization point.** Guarding updates in separate backends does not serialize a common remaining allowance. Ledger lock order, deadlocks, crashes, cancellation and recovery require a new proof.
4. **Installation is substantive.** Current native code needs extension files, build compatibility and trusted preload configuration. Standard RDS cannot install the unchanged unlisted module through normal customer interfaces; managed feasibility is documentary. CloudNativePG/custom images are operator-managed alternatives, not tested DBaaS support. A SQL-only procedure path may be more practical with a narrower contract.
5. **Performance remains inconclusive.** [Support matrix](../../support-matrix.md) records PR #22's unstable benchmark rounds. No percentage overhead or throughput target is established.
