# A — State of AI Write Safety 2026

Research snapshot: **2026-10-13 UTC**. Decision support, not a product commitment. Start with [F — decision memo](F-founder-decision-memo.md); repository findings are in [B](B-technical-gap-analysis.md), proposals in [C](C-creative-feature-discovery.md), sequencing in [D](D-progressive-feature-roadmap.md), and unexecuted experiments in [E](E-reproducible-security-research-plan.md).

## Finding

**INFERRED:** The plausible residual job is verifying and, eventually, bounding actual relational effects under a trusted task identity. It is not generic agent authorization, a new approval dashboard, or simply counting tool calls. Existing controls are strong alternatives. No source examined establishes demand for a paid WriteLeash database product.

Evidence labels throughout this package:

- **OBSERVED:** source code, documentation or artifacts inspected in this review; does not mean independently executed.
- **REPORTED:** a vendor, repository transcript or public participant describes a result.
- **PUBLIC SIGNAL:** a relevant public report, not representative demand or willingness to pay.
- **INFERRED:** analysis derived from identified evidence.
- **HYPOTHESIS:** proposed behavior or opportunity requiring testing.
- **NOT VERIFIED:** evidence absent or insufficient; not a claim that a competitor lacks a capability.

All external links below were accessed on 2026-10-13. Publication/update dates are **NOT VERIFIED** unless explicitly supplied. Documentation describes supported mechanisms; this review did not deploy these services or adversarially test competitors. Absence of a documented atomic database ledger is not evidence that a vendor cannot implement one.

## Residual jobs, without novelty inflation

**HYPOTHESIS:** A developer should be able to ask “Which state actually became durable, under which finite allowance, and can this result be independently falsified?” The immediate value is a comparative research harness. Later candidates are task-wide effect accounting, trusted issuance and ambiguity resolution after lost acknowledgments.

**INFERRED:** Existing grants, RLS, constrained stored procedures, isolation and idempotency should win wherever sufficient. A proxy must not be assumed weaker merely because it observes requests: a narrow trusted tool can accurately bind requests to effects. Conversely a database trigger is not automatically complete merely because it runs inside PostgreSQL. Alternate paths, owners, callback semantics and the policy's meaning decide the boundary.

Market size, adoption, budgets, willingness to pay and required support response times: **NOT VERIFIED**. Technical usefulness and commercial viability remain separate decisions.
