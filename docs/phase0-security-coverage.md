The integrated harness now asserts the positive property in both operation orders (`M` independence forward/reverse: `5|1|20.00`, COMMIT, three fresh-admin oracles) and in the individual-violation-with-savepoint-recovery shape (`R` post-numeric block: `3|1|40.00|t`, poisoned COMMIT rejected, all protected baselines + sibling audit=0 on fresh admin). The historical shared-counter reproduction is retained in git history and in the [runtime report](phase0-security-coverage-run.md) for evidence lineage; it no longer reproduces. Full integrated exact-HEAD transcript archived. Remaining gate: independent maintainer review of this integration; PR #14 stays DRAFT.
2. **Uncharacterized reachable paths:** deeper/mixed exception subtransaction graphs and writer-reachable callable paths should be tested before widening the narrow envelope. Stored `SECURITY DEFINER` functions, FKs and partitions cannot be described as safely excluded in an arbitrary installation merely because this fixture has none. Any *supported* effect that escapes and commits is a security failure: stop for review and propose permanent `CC-REG-YYYY-NNN` test (none yet proven here).
3. **Benchmark:** plan a disposable PG16.4 baseline without the trigger vs protected version with identical synthetic rows, plan, role and warmup; measure p50/p95/p99 latency, transactions/sec and rows/sec for 1/5/100-row updates (100-row budget requires trusted test config). No comparable baseline harness/results exist; **NOT MEASURED**. Owns Issue #15; do not start until this audit is reviewed and merged.

## Transaction-splitting conflict — Route A selected for execution, original checklist unmet

ADR-005 explicitly defers capability-wide budgets, but founder Success Checklist #1 (quoted in [issue #11](https://github.com/MrDarkRoot/CommitCap/issues/11)) says budget excess cannot commit "even transaction splitting." Concrete experiment: writer TX1 updates rows 1–5 and COMMITs, writer TX2 updates rows 6–10 and COMMITs; a fresh admin reads ten changed rows, each individual transaction consumed only 5/5. R's same-backend legacy CC-021 autocommit reuse already does precisely two committed five-event transactions and verifies the exact ten-row state (`R:1704–1716`, E8/E11). This **satisfies the current transaction-local rule**, but **does not** satisfy task-wide budget 5 or the checklist's stronger wording.

- **Route A — SELECTED for Phase 0 execution:** test the narrow statement "Within one top-level transaction, no supported durable relational effect exceeds its **independently declared per-policy** transaction authority, within the precisely tested PostgreSQL/role/schema envelope." Work split across transactions is outside this proof; this cannot claim task-wide safety. ADR-005 remains accepted. The original checklist text is **not** edited or checked; the founder may separately decide on future wording, or wait for stronger evidence.
- **Route B — separate future proof gate, not implemented here:** to satisfy the original "even transaction splitting" wording, require capability-wide durable atomic consumption across transactions/concurrent writers, retries, idempotency keys/ambiguous commit, recovery and monotonic authority (inverse writes cannot launder budget). Canonical CC-034/035, 070/071, 080–082 and 090 would need fresh durable oracles. Route B was **not** selected as this Phase 0 implementation scope, but its proof obligations remain necessary for the unchanged stronger checklist.

The [maintainer explicitly selected Route A](https://github.com/MrDarkRoot/CommitCap/pull/14#issuecomment-5792010006) **only as an execution boundary**. No ADR/checklist was rewritten. **Phase 0 narrow per-transaction independent-policy proof: PASS IN PG16.4 RESEARCH FIXTURE within the precisely tested envelope (row-count, state-transition and numeric-delta policies, both operation orders, savepoint/exception recovery, individual-violation stickiness); unchanged Success Checklist #1 (includes transaction splitting): NOT MET.** These are research-fixture results on this branch, not a supported release claim. #10 separately constrains real managed deployment; local research evidence proves neither deployment nor task-wide safety. PR #14 remains **DRAFT** until a maintainer independently reviews the integrated run; keep issue #11 open until then.
